# Phase 3 — real React corrections; NOT complete or production-ready
## Actual changes compared with Phase 2
App.tsx now uses safeMemberDelete for real member deletion. It checks fresh union/child references, blocks linked people, propagates lookup errors, asks confirmation and verifies one deleted row. This prevents common cascading branch loss; it is not race-proof server enforcement. Concurrent link creation between check and delete remains a blocker.
MemberModal.tsx assigns a stable UUID for the current draft and uses it for member creation and uploaded photo paths. App calls createMemberOnce: lookup same ID, resume/update same member on retry, recover duplicate-key race by reading that row. Members state deduplicates by ID. Lost-response retry is tested with a mock. Closing/reopening or refreshing creates a new draft; this is not durable idempotency across sessions. Concurrent edits need version protection. Separate relationship writes can still partially fail. No delete-and-recreate rollback.
These fixes are integrated in the actual React App, not only the demo. Authentication/dashboard/styles/search/print unchanged. Original member photo fields preserved; new upload record ID now matches draft ID. Standalone HTML unchanged.

## Architecture
Keep React App and family_members identities. family_unions holds parental pair, family_children typed child assignment; do not rewrite a shared union to move one child. Transaction endpoint should atomically save person+union+child changes, preserve existing IDs and unrelated fields, use server ownership checks, stable request receipts, optimistic version and tree locks, and validate cycles. Connection approvals should create references between owned records; never infer identity from names. Existing in-memory Phase 2 workspace remains a reference/simulation, not live persistence.
